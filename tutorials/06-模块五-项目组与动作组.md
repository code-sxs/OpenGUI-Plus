# 06. 模块五：项目组与动作组 `project-group`

## 目标

项目组是配置隔离边界。切换项目组会让项目作用域模块重新加载对应数据；设备池和反馈经验等全局资产按模块规则保留。它适合多个客户、多个 App、多个环境共用一套 OpenGUI-Plus。

## 1. 创建项目组

```bash
node lib/cli.js call project-group.create --json '{
  "name":"客户A-小红书测试",
  "description":"客户A的测试设备、模板和巡检任务",
  "deviceIds":["device_xxx"],
  "tags":["客户A","社媒","测试"]
}'
```

## 2. 查看和切换

```bash
node lib/cli.js call project-group.list
node lib/cli.js call project-group.current
node lib/cli.js call project-group.switch --id <projectId>
```

切换事件会通知宿主，宿主再让各模块 `reseat`。切换后重新查询：

```bash
node lib/cli.js call snippet-library.list
node lib/cli.js call action-template.list
node lib/cli.js call scheduler.list
```

不要在切换过程中并发写多个模块；等待 `projectSwitched` 事件或命令返回后再继续。

## 3. 修改、复制和删除

```bash
node lib/cli.js call project-group.update --json '{
  "id":"<projectId>",
  "description":"增加回放审计要求",
  "tags":["客户A","社媒","测试","审计"]
}'
node lib/cli.js call project-group.duplicate --json '{
  "id":"<projectId>",
  "name":"客户A-小红书-预发布"
}'
node lib/cli.js call project-group.remove --id <projectId>
```

删除项目组会提交清理队列。若它是当前项目，先切换到另一个项目再删除。

## 4. 导出和导入

```bash
node lib/cli.js call project-group.export --id <projectId> > project-group.json
```

导入：

```bash
node lib/cli.js call project-group.import --json '{
  "name":"客户B-测试项目",
  "payload":{ "version":1, "project":{}, "moduleData":{} }
}'
```

实际导出包的字段以命令返回为准。迁移前先用测试数据导入一遍，确认模板里的包名、设备和路径没有带出旧项目内容。

## 5. 项目组和全局数据

| 数据 | 作用域 | 切换行为 |
|---|---|---|
| 无线保存设备 | 全局 | 仍可见；项目组通过 deviceIds 关联 |
| 快捷指令 | 项目 | 随项目切换 |
| 动作模板 | 项目 | 随项目切换 |
| 定时任务 | 项目 | 随项目切换 |
| 回放 | 项目 | 随项目切换 |
| 反馈经验 | 全局知识 | 默认跨项目保留 |
| 设备池 | 由模块实现决定，默认共享设备池 | 通过 groupFilter / project 关联任务 |

## 6. 推荐的项目组命名

```text
<客户或业务>-<App>-<环境>
客户A-设置巡检-测试
内部回归-微信-预发布
个人实验-通用模板-本地
```

项目组不是安全沙箱；它解决的是配置和数据隔离，不替代账号权限、防火墙和凭据管理。
