# 10. 模块九：多机协同与设备池 `device-pool`

## 目标

把多台手机注册进池子，用设备状态、分组、并发上限、任务优先级和自动分配承载批量工作。

## 1. 注册设备

```bash
node lib/cli.js call device-pool.register --json '{
  "name":"测试机-A",
  "serial":"R58M123456A",
  "transport":"usb",
  "groups":["android11","客户A"],
  "maxConcurrency":1,
  "priority":10
}'
```

WiFi 设备也可以注册，serial 填 ADB endpoint：

```json
{"name":"测试机-B","serial":"192.168.1.24:5555","transport":"wifi","groups":["android13","客户A"],"maxConcurrency":2}
```

注册结果中的 `id` 用于后续 `tag`、`setConcurrency`、`assign`。

## 2. 查看设备和分组

```bash
node lib/cli.js call device-pool.list
node lib/cli.js call device-pool.listGroups
node lib/cli.js call device-pool.status
```

状态通常包含 idle、busy、offline 数量和队列长度。

## 3. 修改分组和并发

```bash
node lib/cli.js call device-pool.tag --json '{"id":"<deviceId>","groups":["android13","回归"]}'
node lib/cli.js call device-pool.setConcurrency --json '{"id":"<deviceId>","maxConcurrency":2}'
```

并发上限不是设备性能保证。UI 操作容易互相干扰时应保持 1；只有明确支持多任务隔离时才提高。

## 4. 刷新在线状态

```bash
node lib/cli.js call device-pool.refresh
```

刷新会调用 ADB 探测。offline 设备不会被自动分配新任务。

## 5. 入队任务

payload 是业务对象，设备池只负责任务生命周期和分配，不会猜 payload 应如何执行：

```bash
node lib/cli.js call device-pool.enqueue --json '{
  "payload":{"kind":"template","templateId":"tpl_xxx","variables":{"package":"com.example.app"}},
  "priority":20,
  "groupFilter":"android13",
  "maxAttempts":2
}'
```

优先级越高越先处理；相同优先级通常按入队时间。

## 6. 手动分配和完成

```bash
node lib/cli.js call device-pool.assign --json '{
  "taskId":"<taskId>",
  "deviceId":"<deviceId>"
}'
```

执行实际动作由你的 runner / action-template / DSH 负责。执行结束必须回写：

```bash
node lib/cli.js call device-pool.complete --json '{
  "taskId":"<taskId>",
  "ok":true
}'
```

失败：

```bash
node lib/cli.js call device-pool.complete --json '{
  "taskId":"<taskId>",
  "ok":false,
  "error":"设备在输入步骤断开"
}'
```

## 7. 自动分配

```bash
node lib/cli.js call device-pool.autoAssign
```

它会尽可能把符合分组过滤、在线且有空闲槽位的任务分配出去。可以在外部 worker 中循环：

```text
refresh → autoAssign → 取 running 任务执行 → complete → autoAssign
```

不要无间隔高频轮询；生产环境应使用事件或合理的定时器。

## 8. 取消排队和注销

```bash
node lib/cli.js call device-pool.dequeue --id <taskId>
node lib/cli.js call device-pool.unregister --id <deviceId>
```

运行中的任务不能直接注销，先 `complete` 或处理故障状态。

## 9. 与项目组、回放组合

- 项目组：把设备 ID 关联到客户 / App / 环境。
- 设备池：把任务按 groupFilter 分配给合适设备。
- action-template：payload 中传模板 ID 和变量。
- replay：每台设备的执行都用 taskId / deviceId 作为回放标签。
- feedback-rl：批量执行后按设备型号、App 版本汇总失败经验。
