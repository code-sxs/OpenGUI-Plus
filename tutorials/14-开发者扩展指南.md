# 14. 开发者扩展指南

## 1. 目录结构

```text
src/
├── core/                 # 通用类型、事件、存储、注册表、ADB seam
├── modules/              # 每个业务模块一个目录
├── dsh/adapter.ts        # 可选 DSH 动态适配
├── runtime/              # CLI 和 HTTP/SSE 控制台
├── host.ts               # PlusHost
└── index.ts              # 入口和 defaultModules
```

## 2. 模块接口

模块通过 `defineModule` 创建，核心形状包括：

```ts
const module = defineModule({
  id: 'my-module',
  name: '我的模块',
  version: '0.1.0',
  summary: '一句话说明',
  methods: {
    async ping(input) {
      return ok({ received: input })
    },
  },
  methodSpecs: [
    { name: 'ping', summary: '测试调用', input: { value: '可选值' } },
  ],
  async start(context) { /* load */ },
  async reseat(context) { /* project switch */ },
  async stop() { /* release */ },
  async health() { return { healthy: true, detail: 'ok' } },
})
```

实际接口以 `src/core/module.ts` 为准。方法应返回 `Result`，不要让业务异常穿透到 CLI / DSH 边界。

## 3. 持久化

使用 `context.store` 保存当前项目数据，使用 `context.global` 保存跨项目数据：

```ts
const current = await context.store.get<MyRecord[]>('records', [])
await context.store.set('records', next)
```

`ScopedStore` 会做原子写和同 key 串行化。不要自己直接 `writeFile` 修改 store JSON，也不要把临时状态写进仓库。

## 4. 模块间组合

不要直接 import 另一个业务模块的内部实现。通过：

```ts
await context.call('snippet-library.resolve', { alias: 'health' })
```

事件通过 `context.events.publish` 发布，事件名使用 `PLUS_EVENTS` 中的常量。跨模块依赖在 `ModuleRegistry` 中声明，让启动顺序可控。

## 5. ADB seam

模块使用 `context.adb`，不要直接在业务模块里 spawn `adb`。测试可以注入 `createFakeAdbRunner`，这样没有真机也能验证流程。

需要截图时，把文件写入 `context.dataDir` 下的模块目录，并在删除资源时做 best-effort 清理。

## 6. DSH 适配

`src/dsh/adapter.ts` 负责动态探测 DSH。不要在核心模块顶部静态 import 私有或不可安装的 DSH SDK；否则独立 CLI 和类型检查会被 SDK 可用性绑死。

正确策略：

1. 核心模块保持 Node 标准库 + TypeScript。
2. DSH 能力通过运行时探测。
3. DSH 不存在时返回明确降级状态。
4. 模块不依赖 DSH 才能启动和测试。

## 7. 测试

每个有状态模块至少覆盖：

- 首次启动默认数据。
- 新增、读取、更新、删除。
- 非法输入不修改旧数据。
- stop/start 后持久化仍在。
- 项目切换后的作用域。
- 没有 ADB 时的降级路径。
- 关键模块间调用的失败处理。

测试命令：

```bash
npm run typecheck
npm test
npm run build
npm run check
```

## 8. 注册新模块

在 `src/index.ts` 的 `defaultModules` 添加工厂：

```ts
export const defaultModules = [
  createWirelessConnectionModule(),
  // ...
  createMyModule(),
]
```

同时扩展 `ModuleId` 联合类型，补充 methodSpecs 和文档。控制台的面板是配置驱动的，新增模块时同步加入 `web/index.html`。

## 9. 文档要求

新模块必须至少提供：

- 目标和边界。
- 方法、输入和返回结果。
- 最小单模块示例。
- 至少一个组合示例。
- 持久化位置和作用域。
- 没有 ADB / DSH 时的行为。
- 危险动作和安全注意事项。
- 单元测试与验证命令。

## 10. 提交前检查

```bash
npm run check
git diff --check
git status --short
git diff --stat
```

不要提交：

- `node_modules/`
- `lib/` 编译物（除非项目明确要求发布产物）
- `.opengui-plus/` 本地数据
- 截图、日志、设备配置和凭据
