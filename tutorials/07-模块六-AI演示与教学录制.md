# 07. 模块六：AI 演示与教学录制 `demo-recorder`

## 目标

先由人或 Agent 录制一条“正确做法”，每一步可以保存动作、参数、说明和截图；然后停止录制、查看、修正示范，并转成 action-template。它是人工经验进入自动化系统的入口。

## 1. 开始演示

```bash
node lib/cli.js call demo-recorder.startDemo --json '{
  "name":"标准登录流程",
  "description":"验证码页面出现时先等待，再输入账号"
}'
```

记下 `recordingId`。

## 2. 记录步骤

```bash
node lib/cli.js call demo-recorder.captureStep --json '{
  "recordingId":"<recordingId>",
  "action":"launch",
  "params":{"package":"{{package}}"},
  "note":"启动待教学 App",
  "captureScreen":true
}'

node lib/cli.js call demo-recorder.captureStep --json '{
  "recordingId":"<recordingId>",
  "action":"wait",
  "params":{"ms":1200},
  "note":"等待首页动画结束",
  "captureScreen":true
}'

node lib/cli.js call demo-recorder.captureStep --json '{
  "recordingId":"<recordingId>",
  "action":"tap",
  "params":{"x":160,"y":420},
  "note":"先聚焦账号输入框",
  "captureScreen":true
}'
```

`captureScreen` 默认开启。真机环境会尝试抓 PNG；没有 ADB 或截图失败时，步骤仍可以保存，但没有图片。

## 3. 结束和查看

```bash
node lib/cli.js call demo-recorder.stopDemo --recordingId <recordingId>
node lib/cli.js call demo-recorder.listDemos
node lib/cli.js call demo-recorder.getDemo --id <recordingId>
```

结束后状态变成 `ready`，不应继续追加步骤。

## 4. 修正示范

如果示范顺序不对，使用完整步骤数组替换：

```bash
node lib/cli.js call demo-recorder.revise --json '{
  "id":"<recordingId>",
  "note":"修订：先等待验证码区域出现，再输入账号",
  "steps":[
    {"action":"launch","params":{"package":"{{package}}"},"note":"启动 App"},
    {"action":"wait","params":{"ms":2500},"note":"等待登录页稳定"},
    {"action":"tap","params":{"x":160,"y":420},"note":"聚焦账号框"},
    {"action":"input","params":{"text":"{{username}}"},"note":"输入账号"}
  ]
}'
```

修订会升级 revision；不要直接覆盖原始示范说明，`note` 应解释为什么改。

## 5. 转成动作模板

```bash
node lib/cli.js call demo-recorder.toTemplate --id <recordingId>
```

模块会生成模板结构，并尝试调用 `action-template` 写入。也可以明确通过 `action-template.save-from-demo` 保存，便于控制名称和描述。

## 6. 教学数据写法

好的示范不只是“点了哪里”，还要记录：

- 当前界面为什么判断为目标页面。
- 为什么要等待，而不是立即点击。
- 遇到遮挡、弹窗、权限框时如何恢复。
- 哪些值应该参数化。
- 哪些动作需要人工确认。

坏示范通常是：坐标硬编码但没有前置条件、没有截图、没有说明、把生产账号写进参数、把偶然成功当成稳定流程。

## 7. 与反馈和回放组合

推荐流程：

```text
人工演示 → demo-recorder
       ↓ 转模板
action-template 执行
       ↓ 失败
replay 记录逐帧证据
       ↓ 人工判定
feedback-rl 沉淀原因与恢复方式
       ↓ 修正
demo-recorder.revise → 新版本模板
```

这比直接让 Agent 盲目重复失败流程可靠得多。
