# 08. 模块七：工作流模板市场 `workflow-marketplace`

## 目标

用 `.opengui-workflow` 作为可迁移格式，把多步工作流浏览、安装、运行、评分、导入、导出和发布。当前实现是本地市场目录，内置工作流、已发布工作流和已安装工作流都在本地存储。

## 1. 浏览市场

```bash
node lib/cli.js call workflow-marketplace.categories
node lib/cli.js call workflow-marketplace.browse
node lib/cli.js call workflow-marketplace.browse --json '{
  "category":"app-testing",
  "sort":"rating",
  "query":"设置"
}'
```

分类包括社媒运营、App 测试、自动打卡、数据采集和其他。`browse` 返回模板摘要、来源、下载量和评分。

## 2. 查看详情

```bash
node lib/cli.js call workflow-marketplace.detail --id <workflowId>
```

安装前重点看：

- `taskIntent`：模板想完成什么。
- `preconditions`：设备、权限、登录状态等前置条件。
- `parameters`：哪些值必须填写。
- `steps`：会执行哪些动作。
- `tags` 和作者版本。

## 3. 安装和运行

```bash
node lib/cli.js call workflow-marketplace.install --id <workflowId>
node lib/cli.js call workflow-marketplace.listInstalled
node lib/cli.js call workflow-marketplace.run --json '{
  "id":"<workflowId>",
  "variables":{"package":"com.example.app","keyword":"OpenGUI"}
}'
```

没有 ADB 时，runner 会返回记录但未执行的降级结果。要把它当成真机成功，必须看到每一步 `ok` 且设备有对应变化。

卸载：

```bash
node lib/cli.js call workflow-marketplace.uninstall --id <workflowId>
```

## 4. 评分

```bash
node lib/cli.js call workflow-marketplace.rate --json '{
  "id":"<workflowId>",
  "score":5,
  "comment":"前置条件写得清楚，测试机运行稳定"
}'
```

评分前先实际运行一次；评论里说明设备型号、App 版本和失败条件，比只写“好用”更有价值。

## 5. 导出 `.opengui-workflow`

```bash
node lib/cli.js call workflow-marketplace.exportWorkflow --id <workflowId> > login.opengui-workflow
```

输出是可序列化 JSON，文件扩展名是 `.opengui-workflow`。分享前检查并删除：

- 账号、密码、Token。
- 私有 IP、serial、截图绝对路径。
- 只对本机有效的 shell 命令。
- 生产环境包名或危险操作。

## 6. 导入工作流

```bash
node lib/cli.js call workflow-marketplace.importWorkflow --json '{
  "json":"{\"formatVersion\":1,\"name\":\"示例流程\",\"description\":\"测试\",\"category\":\"app-testing\",\"author\":\"local\",\"version\":\"1.0.0\",\"tags\":[\"demo\"],\"taskIntent\":\"验证登录页\",\"preconditions\":[\"设备已授权\"],\"parameters":[],\"steps":[] }"
}'
```

实际使用时建议从文件读取 JSON，再由 PowerShell / Node.js 组装 payload，避免手写嵌套转义。导入后先 `detail` 审核，再 `install`。

## 7. 发布模板

发布对象必须符合 schema；关键字段至少包括：

```json
{
  "formatVersion": 1,
  "id": "workflow-login",
  "name": "登录页检查",
  "description": "打开 App 并检查登录页",
  "category": "app-testing",
  "author": "local",
  "version": "1.0.0",
  "tags": ["登录", "测试"],
  "taskIntent": "验证登录页面可以打开",
  "preconditions": ["设备已授权", "App 已安装"],
  "parameters": [{"name":"package","label":"App 包名","required":true}],
  "steps": [{"id":"s1","action":"launch","params":{"package":"{{package}}"}}]
}
```

```bash
node lib/cli.js call workflow-marketplace.publish --json '{"template":<上面的对象>}'
```

不要发布未经测试、含秘密、含绕过授权或会造成不可逆影响的模板。

## 8. 与 action-template 的选择

- `action-template`：项目内部的可编辑动作模板，适合快速迭代。
- `workflow-marketplace`：带 schema、分类、版本、评分和交换格式，适合分享和迁移。
- `demo-recorder`：从人工演示产生素材。

常见路径：`demo-recorder → action-template → workflow-marketplace`。
