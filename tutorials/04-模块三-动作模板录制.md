# 04. 模块三：动作模板录制 `action-template`

## 目标

把多步动作保存为模板。每一步有类型和 params，参数中可以写 `{{变量名}}`；停止录制后自动提取变量，执行时传入值。

## 1. 支持的步骤类型

| 类型 | 用途 | 常见 params |
|---|---|---|
| `connect` | 连接设备 | `mode`、`id` |
| `disconnect` | 断开设备 | 无 |
| `launch` | 启动 App | `package`、`activity` |
| `shell` | 执行受控 shell / ADB 指令 | `command` |
| `tap` | 点击 | `x`、`y` 或目标信息 |
| `swipe` | 滑动 | `x1`、`y1`、`x2`、`y2`、`durationMs` |
| `input` | 输入文本 | `text`、`target` |
| `screenshot` | 截图 | `path` 或说明 |
| `wait` | 等待 | `ms` |
| `snippet` | 调用快捷指令 | `alias` |

动作的实际执行能力取决于当前 DSH / ADB 适配器；没有设备时，模板仍可以录制、查看和做结构校验。

## 2. 开始录制

```bash
node lib/cli.js call action-template.startRecording --json '{
  "name":"打开设置并检查版本",
  "description":"一个可重复的设置页巡检流程"
}'
```

记下返回的 `recordingId`。

## 3. 追加步骤

```bash
node lib/cli.js call action-template.recordStep --json '{
  "recordingId":"<recordingId>",
  "type":"connect",
  "params":{"mode":"auto"},
  "note":"连接当前首选设备"
}'

node lib/cli.js call action-template.recordStep --json '{
  "recordingId":"<recordingId>",
  "type":"launch",
  "params":{"package":"{{package}}"},
  "note":"启动待检查的 App"
}'

node lib/cli.js call action-template.recordStep --json '{
  "recordingId":"<recordingId>",
  "type":"wait",
  "params":{"ms":1500}
}'

node lib/cli.js call action-template.recordStep --json '{
  "recordingId":"<recordingId>",
  "type":"screenshot",
  "params":{"path":"{{screenshotPath}}"}
}'
```

## 4. 停止录制并查看模板

```bash
node lib/cli.js call action-template.stopRecording --recordingId <recordingId>
node lib/cli.js call action-template.list
```

停止后会生成模板 id 和变量列表，变量通常包括 `package`、`screenshotPath`。

```bash
node lib/cli.js call action-template.get --id <templateId>
```

## 5. 执行模板

```bash
node lib/cli.js call action-template.execute --json '{
  "id":"<templateId>",
  "variables":{
    "package":"com.android.settings",
    "screenshotPath":"D:/opengui-runs/settings.png"
  }
}'
```

执行结果包含：

- `ok`：整体是否成功。
- `results`：每一步的 stepId、type、ok、detail、skipped。
- `runCount`：模板累计执行次数。

如果缺少必需变量，执行前会失败，不会悄悄把 `{{变量}}` 当成真实参数执行。

## 6. 直接更新模板

```bash
node lib/cli.js call action-template.update --json '{
  "id":"<templateId>",
  "name":"打开设置并检查版本-v2",
  "description":"增加等待时间",
  "steps":[
    {"type":"connect","params":{"mode":"auto"}},
    {"type":"launch","params":{"package":"{{package}}"}},
    {"type":"wait","params":{"ms":2500}},
    {"type":"screenshot","params":{"path":"{{screenshotPath}}"}}
  ]
}'
```

更新后变量会重新提取。删除：

```bash
node lib/cli.js call action-template.remove --id <templateId>
```

## 7. 从演示录制生成模板

`demo-recorder.toTemplate` 会把演示步骤转换成模板；也可以调用 `save-from-demo` 直接写入动作模板模块：

```bash
node lib/cli.js call action-template.save-from-demo --json '{
  "name":"从演示生成的登录模板",
  "description":"人工确认后的版本",
  "steps":[
    {"action":"launch","params":{"package":"{{package}}"},"note":"启动 App"},
    {"action":"tap","params":{"x":120,"y":360}},
    {"action":"input","params":{"text":"{{username}}"}}
  ]
}'
```

## 8. 模板设计建议

- 把设备连接、启动 App、等待、核心操作、截图、断开分成清晰步骤。
- 任何会变化的包名、账号、关键词、坐标、路径都参数化。
- 用 `note` 写“为什么做这一步”，便于 AI 和人工复核。
- 对不可逆动作在步骤前加确认或拆成独立模板。
- 先用一台测试设备跑通，再接入 scheduler 或 device-pool。
