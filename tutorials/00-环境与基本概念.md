# 00. 环境、数据目录与基本概念

## 1. OpenGUI-Plus 到底是什么

OpenGUI-Plus 是叠加在 OpenGUI 上的独立 DSH 插件层。可以把它理解为三层：

```text
Android 手机 / 模拟器
        ↓ ADB、Accessibility、GUI Agent
上游 OpenGUI：看屏幕、规划、点击、输入、执行
        ↓ ModuleContext.call + EventBus
OpenGUI-Plus：设备资产、模板、调度、经验、设备池、回放
```

增强层的业务代码不直接绑死 DSH SDK。运行时能探测到 DSH 就注册适配器；没有 DSH 时仍可以使用 CLI、HTTP 控制台和测试替身。这样可以先在电脑上整理资产，再接入真机。

## 2. 环境要求

| 项目 | 要求 |
|---|---|
| Node.js | `>=22.5.0`（建议使用 Node 22 LTS 或更高版本） |
| ADB | 真机动作和设备探测需要；只看数据、写模板、跑单元测试时可选 |
| Android | 建议 Android 11+；无线配对需要 Android 11+ 的无线调试能力 |
| DSH | 接入 DSH 时使用受支持的 DSH 版本；独立 CLI 不要求安装 DSH |
| 网络 | 安装依赖、安装 DSH 或调用外部模型时需要；本地模块本身不强制联网 |

先确认版本：

```bash
node --version
npm --version
adb version
adb devices -l
```

如果 `adb` 不存在，先安装 Android SDK Platform Tools，并把 `adb` 放进 PATH。Windows 下重新打开终端后再验证。

## 3. 安装与构建

```bash
cd deepseek-harness-plugin/opengui-plus
npm install
npm run typecheck
npm test
npm run build
```

推荐第一次执行 `npm run check`，它会依次做类型检查、Vitest 测试和构建：

```bash
npm run check
```

构建成功后会生成 `lib/`。`lib/` 是编译产物，不要手动编辑；源代码在 `src/`。

## 4. 数据目录

默认目录：

- Windows：`C:\Users\<用户名>\.opengui-plus\`
- macOS / Linux：`~/.opengui-plus/`

覆盖方式按优先级使用：

```bash
node lib/cli.js serve --data-dir D:\opengui-data
```

或：

```powershell
$env:OPENGUI_PLUS_DATA_DIR = 'D:\opengui-data'
node lib/cli.js status
```

数据由 `PlusStore` 管理，采用项目作用域和全局作用域：

- 全局数据：已保存的无线设备、跨项目反馈经验等。
- 项目数据：快捷指令、动作模板、定时任务、回放、市场安装项等。
- 项目组切换后，模块通过 `reseat` 重新指向新的项目数据。

不要把真实设备地址、令牌、账号和截图提交到 Git。建议把数据目录放在仓库之外，并加入备份策略。

## 5. CLI、控制台和 DSH 的关系

同一套模块有三种入口：

1. **CLI**：适合脚本、批处理、排障和文档示例。
2. **HTTP + SSE 控制台**：适合查看模块、点击操作和观察实时事件。
3. **DSH 动态适配**：适合在 DSH 对话里让模型调用插件方法。

三者调用的是同一个 `PlusHost` 和 `ModuleRegistry`，不会各自维护一份数据。

## 6. 第一次启动检查

```bash
node lib/cli.js status
node lib/cli.js modules
```

`modules` 应该能看到十个模块和它们的方法列表。没有 ADB 时，模块仍会启动，但连接、截图和实际动作会返回降级结果；这时先继续阅读模板、市场和项目组教程即可。

## 7. 安全边界

- 真实发送、发布、删除、购买、账号变更等动作必须由操作者确认。
- 不要把生产账号凭据写进模板或工作流文件。
- 不要把截图、设备 serial、IP、WiFi 配对码上传到公开仓库。
- 定时任务和设备池属于“会自动执行”的能力，启用前先用 `runNow` 或低风险测试任务验证。
- 导入第三方 `.opengui-workflow` 前先读清楚步骤、目标包名、shell 命令和前置条件。
