# 13. 排障、备份与安全运维

## 1. CLI 启动失败

```bash
node --version
npm install
npm run typecheck
npm run build
node lib/cli.js status
```

常见原因：

- 没有先构建，`lib/cli.js` 不存在。
- Node 版本过低。
- `node_modules` 不完整。
- 当前目录不是 `deepseek-harness-plugin/opengui-plus`。

## 2. 类型检查或测试失败

```bash
npm run typecheck
npm test
npm run check
```

先看第一条错误，不要被后续连锁错误带偏。修改源码后重新构建；不要直接修改 `lib/`。

## 3. ADB 设备问题

```bash
adb kill-server
adb start-server
adb devices -l
node lib/cli.js call wlan-connection.discover
node lib/cli.js call wlan-connection.status
```

状态处理：

| 状态 | 处理 |
|---|---|
| `device` | 可继续 |
| `unauthorized` | 解锁手机并确认授权 |
| `offline` | 重启 ADB、检查 USB / WiFi |
| 没有任何设备 | 检查驱动、线缆、IP、端口和调试开关 |

## 4. WiFi ADB 问题

确认：

1. 手机和电脑在同一网络或可路由网络。
2. 手机无线调试开关打开。
3. 配对端口和调试端口没有混淆。
4. Windows 防火墙没有拦截 ADB。
5. `adb connect host:port` 手工执行结果正常。

如果手工 ADB 都失败，不要继续排查插件。

## 5. 连接成功但动作不执行

连接模块的 `connected` 只说明 ADB 通道可用，不代表 App 已在前台或 AccessibilityService 已授权。检查：

- DSH 是否选中了正确设备。
- OpenGUI 客户端是否已安装和启动。
- 无障碍服务、悬浮窗、电池优化权限。
- 模板步骤是否被标记为 `skipped`。
- `replay` 中第一个失败帧的 `detail`。

## 6. 数据“看起来丢了”

先确认数据目录和项目：

```bash
node lib/cli.js status --data-dir D:\opengui-data
node lib/cli.js call project-group.current --data-dir D:\opengui-data
node lib/cli.js call snippet-library.list --data-dir D:\opengui-data
```

常见原因：

- 换了 `--data-dir`。
- `OPENGUI_PLUS_DATA_DIR` 覆盖了命令行默认值。
- 切到了另一个项目组。
- 只查看了项目数据，实际资产在全局作用域。

## 7. 备份

推荐备份整个数据目录，先停止正在写数据的控制台：

```powershell
$src = "$env:USERPROFILE\.opengui-plus"
$dst = "D:\backup\opengui-plus-$(Get-Date -Format yyyyMMdd-HHmmss)"
Copy-Item $src $dst -Recurse -Force
```

恢复前先把当前目录改名保留，不要直接覆盖唯一副本。恢复后检查：

```bash
node lib/cli.js status --data-dir D:\backup\opengui-plus-...
node lib/cli.js modules --data-dir D:\backup\opengui-plus-...
```

## 8. 调度问题

```bash
node lib/cli.js call scheduler.list
node lib/cli.js call scheduler.nextRuns --limit 20
node lib/cli.js call scheduler.runs --limit 50
node lib/cli.js call scheduler.tick
```

判断顺序：

1. 任务是否存在。
2. 是否 `enabled`。
3. `nextRunAt` 是否符合时区预期。
4. target 是否仍指向存在的 snippet / template。
5. 运行日志的 error。
6. 设备池是否有在线设备。

## 9. 导入失败

- snippet 导入：检查 `version`、alias 唯一性、command 非空。
- project 导入：先在测试数据目录执行，避免污染生产项目。
- workflow 导入：先读 JSON 和 steps，确认 schema、前置条件和参数。
- 导入前后都执行 list / detail，确认数量、版本和 ID。

## 10. 回放排障

```bash
node lib/cli.js call replay.stats --id <sessionId>
node lib/cli.js call replay.getReplay --id <sessionId>
node lib/cli.js call replay.exportReplay --json '{"id":"<sessionId>","format":"html"}'
```

优先修复第一个失败帧。后面的失败可能只是前面状态错误的连锁结果。

## 11. 安全检查

发布或分享前运行人工检查：

- 不包含 `.opengui-plus` 数据目录。
- 不包含 `node_modules`、`lib` 临时产物和截图。
- 不包含 adb serial、手机 IP、配对码、Token、账号和密码。
- 不包含会直接发布、删除、购买或修改账号的未确认动作。
- 工作流写清楚风险、权限和前置条件。
- 控制台只监听 `127.0.0.1`，除非你有明确的认证和网络隔离。

## 12. 版本和回滚

发布前：

```bash
npm run check
git diff --check
git status --short
```

文档、模板和工作流建议使用版本号；数据备份以时间戳命名。不要通过删除数据来“回滚”，优先恢复备份到新目录并用 `--data-dir` 验证。
