# 01. 启动方式与通用调用规范

## 1. 构建后直接运行

```bash
cd deepseek-harness-plugin/opengui-plus
npm run build
node lib/cli.js help
```

如果已经把包安装到 PATH，也可以使用：

```bash
opengui-plus help
```

开发阶段更建议用 `node lib/cli.js`，因为它明确指向当前工作区的编译结果。

## 2. 启动控制台

```bash
node lib/cli.js serve --host 127.0.0.1 --port 8787
```

看到类似下面的输出后，用浏览器打开地址：

```text
OpenGUI-Plus 控制台已启动: http://127.0.0.1:8787
数据目录: C:\Users\...\.opengui-plus
按 Ctrl+C 停止
```

控制台使用 SSE 接收事件。连接状态变化、模板执行、任务触发、项目切换、反馈记录、回放就绪等事件会实时出现在页面上。

监听局域网时：

```bash
node lib/cli.js serve --host 0.0.0.0 --port 8787
```

除非明确需要，不建议监听 `0.0.0.0`；控制台可以操作设备，暴露到局域网会扩大风险。

## 3. 查看模块

```bash
node lib/cli.js modules
```

输出包含：模块 ID、启动状态、中文名称、摘要和方法列表。模块 ID 是后续 `call` 的前缀，例如：

```text
snippet-library  →  snippet-library.save
replay           →  replay.exportReplay
```

## 4. 调用方法的两种写法

简单参数：

```bash
node lib/cli.js call snippet-library.complete --prefix sc
```

复杂参数用 `--json`：

```bash
node lib/cli.js call action-template.execute \
  --json '{"id":"tpl_xxx","variables":{"package":"com.example.app"}}'
```

也可以把复杂对象作为字符串传进去，但方法本身是否解析字符串取决于模块。最稳妥的规则是：

- 数字、布尔值、短字符串：用 `--key value`。
- 数组、对象、嵌套对象：用 `--json`。
- 需要传给模块的 JSON 字段（如 `payload`、`steps`、`anomaly`）：先看对应教程中的格式。

CLI 会把 `true`、`false` 和纯数字自动转换成布尔值或数字。

## 5. 返回值和错误

模块内部统一返回 `Result<T>`：

```ts
{ ok: true, value: ... }
{ ok: false, error: '错误说明' }
```

CLI 成功时直接打印 `value`；失败时打印：

```text
错误: 会话不存在
```

脚本中应该检查进程退出码：

```bash
node lib/cli.js call replay.getReplay --id nope
if %ERRORLEVEL% NEQ 0 echo 失败
```

PowerShell：

```powershell
node lib/cli.js call replay.getReplay --id nope
if ($LASTEXITCODE -ne 0) { Write-Error '调用失败' }
```

## 6. ID 的传递原则

绝大多数资源都是运行时生成 ID：

```text
startRecording → sessionId
save            → snippet.id
startDemo       → recordingId
startRecording  → template recordingId
project-group.create → project.id
```

不要手写或猜 ID。把上一条命令的输出保存下来，再传给下一条。批处理可以用 PowerShell / Node.js 解析 JSON；人工操作则复制输出中的 ID。

## 7. 数据和状态检查

```bash
node lib/cli.js status
node lib/cli.js call snippet-library.list
node lib/cli.js call action-template.list
node lib/cli.js call scheduler.list
node lib/cli.js call device-pool.status
node lib/cli.js call replay.listReplays
```

## 8. DSH 中的使用思路

在 DSH 中不必记住全部 CLI 命令。让 DSH 调用对应模块方法即可，例如：

```text
请调用 wlan-connection.discover，列出当前 ADB 设备；不要执行连接。
请调用 snippet-library.complete，prefix 使用 sc。
请调用 replay.listReplays，列出最近的执行回放。
```

涉及真实动作时，明确告诉模型：先观察、先确认目标设备、不要自动执行高风险动作。DSH 不可用时仍可用 CLI 验证模块逻辑。
