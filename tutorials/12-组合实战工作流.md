# 12. 组合实战：从连接到批量回放

这篇把十个模块串成一条完整链路。示例目标：对一组 Android 测试设备执行 App 检查，失败时保留回放，人工复核后把经验沉淀下来。

## 场景结构

```text
project-group：客户A-回归测试
  ├─ wlan-connection：保存和连接设备
  ├─ snippet-library：health / collect-log
  ├─ demo-recorder：录制标准检查示范
  ├─ action-template：参数化检查模板
  ├─ workflow-marketplace：导入或导出工作流
  ├─ scheduler：每天夜间触发
  ├─ device-pool：多台设备排队和分配
  ├─ replay：每次执行逐帧记录
  └─ feedback-rl：失败原因和恢复经验
```

## 第一步：建立项目组

```bash
node lib/cli.js call project-group.create --json '{
  "name":"客户A-回归测试",
  "description":"客户A App 的夜间回归",
  "tags":["客户A","回归","夜间"]
}'
node lib/cli.js call project-group.switch --id <projectId>
```

## 第二步：准备设备

发现并保存设备：

```bash
node lib/cli.js call wlan-connection.discover
node lib/cli.js call wlan-connection.saveDevice --json '{"name":"回归-A","transport":"usb","serial":"R58M123456A"}'
node lib/cli.js call wlan-connection.saveDevice --json '{"name":"回归-B","transport":"wifi","host":"192.168.1.24","port":5555}'
node lib/cli.js call wlan-connection.listDevices
```

注册到设备池：

```bash
node lib/cli.js call device-pool.register --json '{"name":"回归-A","serial":"R58M123456A","transport":"usb","groups":["客户A","回归"],"maxConcurrency":1}'
node lib/cli.js call device-pool.register --json '{"name":"回归-B","serial":"192.168.1.24:5555","transport":"wifi","groups":["客户A","回归"],"maxConcurrency":1}'
node lib/cli.js call device-pool.refresh
```

项目组创建后再把设备池返回的 ID 填进项目组 `deviceIds`。

## 第三步：建立快捷指令

```bash
node lib/cli.js call snippet-library.save --json '{
  "alias":"health",
  "command":"检查 App 是否启动、当前 Activity、截图和设备连接",
  "tags":["回归","巡检"],
  "description":"回归任务开始前的健康检查"
}'
node lib/cli.js call snippet-library.save --json '{
  "alias":"collect-log",
  "command":"收集本次测试日志并保存到指定目录",
  "tags":["回归","日志"]
}'
```

## 第四步：录制人工标准示范

```bash
node lib/cli.js call demo-recorder.startDemo --json '{"name":"App回归标准检查","description":"启动、等待、检查首页、截图"}'
```

加入 launch、wait、screenshot、snippet 等步骤：

```bash
node lib/cli.js call demo-recorder.captureStep --json '{"recordingId":"<recordingId>","action":"launch","params":{"package":"{{package}}"},"note":"启动目标 App"}'
node lib/cli.js call demo-recorder.captureStep --json '{"recordingId":"<recordingId>","action":"wait","params":{"ms":2000},"note":"等待首页稳定"}'
node lib/cli.js call demo-recorder.captureStep --json '{"recordingId":"<recordingId>","action":"snippet","params":{"alias":"health"},"note":"执行健康检查"}'
node lib/cli.js call demo-recorder.captureStep --json '{"recordingId":"<recordingId>","action":"screenshot","params":{"path":"{{reportPath}}"},"note":"保存结果"}'
node lib/cli.js call demo-recorder.stopDemo --recordingId <recordingId>
node lib/cli.js call demo-recorder.toTemplate --id <recordingId>
```

## 第五步：先单机执行模板

```bash
node lib/cli.js call action-template.list
node lib/cli.js call action-template.execute --json '{
  "id":"<templateId>",
  "variables":{"package":"com.example.app","reportPath":"D:/reports/run-a.png"}
}'
```

执行前后配套回放：

```bash
node lib/cli.js call replay.startRecording --json '{"name":"单机回归-回归-A","taskLabel":"project=客户A;template=<templateId>;device=A"}'
node lib/cli.js call replay.markFrame --json '{"sessionId":"<sessionId>","action":"execute template","decision":"开始单机验证","ok":true}'
node lib/cli.js call replay.stopRecording --sessionId <sessionId>
```

先单机验证，确认模板和动作都稳定后，再进入调度和批量阶段。

## 第六步：交给设备池批量执行

```bash
node lib/cli.js call device-pool.enqueue --json '{
  "payload":{"kind":"template","templateId":"<templateId>","variables":{"package":"com.example.app"}},
  "priority":20,
  "groupFilter":"回归",
  "maxAttempts":2
}'
node lib/cli.js call device-pool.enqueue --json '{
  "payload":{"kind":"template","templateId":"<templateId>","variables":{"package":"com.example.app"}},
  "priority":20,
  "groupFilter":"回归",
  "maxAttempts":2
}'
node lib/cli.js call device-pool.autoAssign
node lib/cli.js call device-pool.status
```

外部执行器拿到 running 任务后：

1. 为 task 创建 replay session。
2. 逐步调用 `markFrame`。
3. 执行结束调用 `stopRecording`。
4. 根据结果调用 `device-pool.complete`。

## 第七步：设置夜间定时

模板单机验证稳定后再启用：

```bash
node lib/cli.js call scheduler.create --json '{
  "name":"客户A夜间回归",
  "schedule":{"kind":"cron","expression":"0 2 * * *"},
  "target":{"type":"template","id":"<templateId>","variables":{"package":"com.example.app"}},
  "enabled":true
}'
```

如果需要多机分配，把 scheduler 目标改成外部 flow / 队列入口，让它创建 device-pool 任务，而不是绕过设备池直接执行。

## 第八步：失败复盘和经验沉淀

```bash
node lib/cli.js call replay.listReplays
node lib/cli.js call replay.stats --id <sessionId>
node lib/cli.js call replay.exportReplay --json '{"id":"<sessionId>","format":"html"}'
node lib/cli.js call feedback-rl.record --json '{
  "taskLabel":"客户A夜间回归",
  "outcome":"failure",
  "symptom":"启动后首页加载超过默认等待时间",
  "step":"wait",
  "resolution":"将 wait 从 2000ms 调整为 5000ms，并增加截图确认",
  "context":{"templateId":"<templateId>","device":"回归-B"}
}'
```

修订 demo 或模板，再重新跑一台设备。确认经验奏效后：

```bash
node lib/cli.js call feedback-rl.queryRelevant --symptom 首页加载超时
node lib/cli.js call feedback-rl.markApplied --json '{"experienceId":"<experienceId>","worked":true}'
```

## 第九步：发布稳定工作流

模板经过多次回归后，导出并审核：

```bash
node lib/cli.js call workflow-marketplace.exportWorkflow --id <workflowId> > customer-a-regression.opengui-workflow
```

发布前清理项目私密信息，升级版本号，并写明 preconditions、参数、设备要求和已知限制。

## 完整验收清单

- [ ] 设备 USB / WiFi 连接均可用。
- [ ] 项目组切换后，模板和 snippet 没串项目。
- [ ] 模板缺少变量时会明确失败。
- [ ] 单机动作成功后才启用设备池。
- [ ] 设备离线时不会被分配新任务。
- [ ] scheduler 的 `nextRuns` 时间符合预期。
- [ ] 每次批量任务都有 replay session。
- [ ] 失败任务都有人工反馈或明确错误。
- [ ] 工作流文件不含凭据、私有地址和敏感截图。
- [ ] `npm run check` 在发布前通过。
