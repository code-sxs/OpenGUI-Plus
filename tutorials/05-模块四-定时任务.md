# 05. 模块四：定时任务 `scheduler`

## 目标

将 snippet、action-template 或 flow 交给调度器，支持单次、每天、每周、Cron，并保留执行日志。调度器本身不保证设备永远在线；目标执行失败会进入日志，应该配合设备池和回放排查。

## 1. 任务结构

每个任务包含：

- `name`：任务名。
- `schedule`：计划对象。
- `target`：执行目标。
- `enabled`：是否启用。
- `nextRunAt`：下一次运行时间，由模块计算。

目标通常是：

```json
{"type":"snippet","alias":"health"}
{"type":"template","id":"tpl_xxx","variables":{"package":"com.example.app"}}
{"type":"flow","steps":[{"module":"snippet-library","method":"resolve","input":{"alias":"health"}}]}
```

## 2. 单次任务

```bash
node lib/cli.js call scheduler.create --json '{
  "name":"一次性巡检",
  "schedule":{"kind":"once","at":"2026-09-05T10:00:00+08:00"},
  "target":{"type":"snippet","alias":"health"},
  "enabled":true
}'
```

时间使用 ISO 8601。建议明确时区偏移，不要依赖机器时区。

## 3. 每日任务

```bash
node lib/cli.js call scheduler.create --json '{
  "name":"每日早检",
  "schedule":{"kind":"daily","at":"09:30"},
  "target":{"type":"snippet","alias":"health"},
  "enabled":true
}'
```

## 4. 每周任务

```bash
node lib/cli.js call scheduler.create --json '{
  "name":"工作日检查",
  "schedule":{"kind":"weekly","weekdays":[1,2,3,4,5],"at":"09:30"},
  "target":{"type":"template","id":"<templateId>","variables":{"package":"com.example.app"}},
  "enabled":true
}'
```

星期数以模块实现和文档约定为准；使用前可用 `nextRuns` 验证，不要凭感觉上线。

## 5. Cron 任务

```bash
node lib/cli.js call scheduler.create --json '{
  "name":"每两小时巡检",
  "schedule":{"kind":"cron","expression":"0 */2 * * *"},
  "target":{"type":"snippet","alias":"health"},
  "enabled":true
}'
```

Cron 是五段：分钟、小时、日期、月份、星期。先用一个近期时间验证表达式，再设置长期任务。

## 6. 查看、启停和立即执行

```bash
node lib/cli.js call scheduler.list
node lib/cli.js call scheduler.nextRuns --limit 10
node lib/cli.js call scheduler.disable --id <taskId>
node lib/cli.js call scheduler.enable --id <taskId>
node lib/cli.js call scheduler.runNow --id <taskId>
node lib/cli.js call scheduler.runs --limit 20
```

`runNow` 不改变原计划，只额外执行一次。调度器启动时和内部 tick 会检查到期任务；测试时可手动调用：

```bash
node lib/cli.js call scheduler.tick
```

## 7. 修改和删除

```bash
node lib/cli.js call scheduler.update --json '{
  "id":"<taskId>",
  "schedule":{"kind":"daily","at":"10:00"},
  "enabled":false
}'
node lib/cli.js call scheduler.remove --id <taskId>
```

删除前先用 `runs` 留存必要日志；删除后不能依赖任务 ID 恢复。

## 8. 组合建议

- `snippet-library`：维护可复用目标。
- `action-template`：承载多步动作和变量。
- `scheduler`：只负责何时触发。
- `replay`：在模板或流程执行周围记录过程。
- `feedback-rl`：根据日志和人工判定沉淀经验。

## 9. 防止误执行

- 先创建 `enabled:false` 的任务，用 `runNow` 测试。
- 目标里不要直接写生产账号和不可逆操作。
- 为任务名称写明设备、项目、频率和风险，例如 `客户A-测试机-每日巡检`。
- 设备离线时任务会失败；要做批量可靠执行，使用 device-pool 的排队和自动分配。
