# 02. 模块一：无线调试连接 `wlan-connection`

## 目标

统一管理 USB、WiFi 和自动连接；保存设备配置；查询 ADB 状态；支持 Android 11+ 的**六位配对码配对**和**二维码配对**（含 mDNS 自动解析配对端口），以及 USB 切 TCP/IP。

## 1. 先发现设备

```bash
node lib/cli.js call wlan-connection.discover
```

典型返回会包含 serial、state、transport 等信息：

- `device`：已授权且在线。
- `unauthorized`：手机上没有确认 USB 调试授权。
- `offline`：设备枚举到了，但当前不可用。
- `no permissions`：电脑端 ADB 权限或驱动有问题。

Windows 常见检查：重新插拔 USB、确认手机已解锁、在手机上点击“允许 USB 调试”、执行 `adb kill-server && adb start-server`。

## 2. 保存 USB 设备

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{
  "name":"测试机-USB",
  "transport":"usb",
  "serial":"R58M123456A"
}'
```

USB 设备至少应有 `serial`。`name` 是给人看的备注名。

## 3. 保存 WiFi 设备

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{
  "name":"测试机-WiFi",
  "transport":"wifi",
  "host":"192.168.1.23",
  "port":5555
}'
```

端口默认 5555。设备和电脑必须在可互通网络中，且 Android 端已经开启无线调试或通过 USB 执行过 TCP/IP 切换。

```bash
node lib/cli.js call wlan-connection.listDevices
```

保存设备使用全局作用域，切换项目组后仍可复用。

## 4. 设置连接模式

```bash
node lib/cli.js call wlan-connection.setMode --json '{"mode":"auto","autoConnect":true}'
```

模式含义：

| 模式 | 行为 |
|---|---|
| `usb` | 优先使用 USB serial |
| `wifi` | 使用保存的 host:port |
| `auto` | 根据当前可见设备和保存配置自动选择 |

查看状态：

```bash
node lib/cli.js call wlan-connection.status
```

连接：

```bash
node lib/cli.js call wlan-connection.connect --mode auto
node lib/cli.js call wlan-connection.connect --id <deviceId>
node lib/cli.js call wlan-connection.disconnect
```

## 5. Android 11+ 配对：先分清两个端口

Android 11 之后，无线调试不再靠 `adb tcpip 5555` 一条命令搞定，而是分成**配对**和**连接**两件事。绝大多数连不上的情况，都是把这两个端口搞混了。

| | 配对端口 | 连接端口 |
|---|---|---|
| 用途 | 让手机信任这台电脑（一次性） | 真正用来跑 adb 命令 |
| 在哪看 | 「使用配对码配对设备」页面显示的 `IP:端口` | 无线调试主界面显示的 `IP:端口` |
| 典型值 | 随机，如 `39443`、`41000`，每次打开都会变 | 通常是 `5555` |
| 什么时候用 | `pairWithCode` / `pairWithQr` / `pairAndConnect` | `connect` / `saveDevice` |
| 记在哪 | 设备档案的 `pairingPort` 字段 | 设备档案的 `wifi` 字段 |

给 AI 打电话时最容易踩的坑：把配对端口当成连接端口传给 `connect`，会一直报 `cannot connect`。`pairAndConnect` 存在的意义就是替你把这两步接起来。

配对入口有两个，手机端和本模块一一对应：

| 手机上的入口 | 本模块方法 | 你需要提供的东西 |
|---|---|---|
| 无线调试 → 使用配对码配对设备 | `pairWithCode` | `host`、`port`（配对端口）、`code`（6 位） |
| 无线调试 → 使用二维码配对设备 | `pairWithQr` | 二维码文本（`qrText`）或图片路径（`image`） |

`pair` 是统一入口：传了 `qr`/`qrText`/`image` 就走二维码流程，否则走配对码流程。平时直接用 `pairAndConnect` 更省事。

## 6. 六位配对码配对

### 手机上的操作

1. 设置 → 开发者选项 → 无线调试 → 打开开关。
2. 点「使用配对码配对设备」。
3. 屏幕上会出现 `IP 地址和端口`（例如 `192.168.1.23:39443`）和 `WLAN 配对码`（6 位数字）。
4. **保持这个页面不要退出**，配对码只在页面停留期间有效。

### 命令行

```bash
node lib/cli.js call wlan-connection.pairWithCode --json '{
  "host":"192.168.1.23",
  "port":39443,
  "code":"123456"
}'
```

成功返回：

```json
{
  "paired": true,
  "endpoint": { "host": "192.168.1.23", "port": 39443 },
  "guid": "adb-3f2a…",
  "message": "Successfully paired to 192.168.1.23:39443 [guid=adb-3f2a…]",
  "hint": "配对只授权本机一次；连接要用 adb 连接端口（通常 5555），可调用 pairAndConnect 一步完成。"
}
```

配对**不等于**连上。配对只是让手机记住这台电脑，接下来还要 `connect` 到连接端口。

### 配对码的写法很宽容

`code` 可以是 `"123456"`，也可以是用户口述的 `"123 456"`、`"12-34-56"` —— 空格和连字符会被自动去掉。非数字、位数不在 4–12 位之间会直接报错，不会拿去喂给 adb。

### adb 版本兼容

老版本 platform-tools 的 `adb pair` 是交互式的（提示 `Enter pairing code:`），新版本支持把配对码作为参数。模块两条路都试：先写 stdin，失败再退化成参数形式。所以不用关心你装的是哪个版本的 adb。

## 7. 二维码配对

### 为什么命令行里没有“扫一扫”

电脑端的二维码配对，前提是电脑有摄像头去拍手机屏幕 —— 这个仓库是 CLI/插件形态，拿不到摄像头。所以二维码需要你先用别的方式扫出来，再交给模块：

1. **用另一台手机 / 微信 / 系统扫码工具扫**，把扫出来的那段文本粘给 `qrText`（最省事，零依赖）。
2. **截图保存成图片**，把路径交给 `image`，由本机装的 `zbarimg` 解码。
3. 直接跳过发现：手动把配对码页面上的 `host` + `port` 一起传进来。

### 二维码长什么样

Android 原生和小米 HyperOS 生成的格式一致：

```text
WIFI:T:ADB;S:studio-abc123._adb-tls-pairing._tcp;P:123456;;
```

| 字段 | 含义 |
|---|---|
| `WIFI:T:ADB;` | 固定前缀，用来确认这是无线调试配对码而不是别的东西 |
| `S:` | 服务名（mDNS 名）。部分 ROM 会在这里直接放 `host:port` |
| `P:` | 6 位配对码 |

**关键点**：标准格式里的 `S:` 是服务名，不是地址。要拿到 `host:port`，必须查一次 mDNS（模块会自动做）。这就是为什么下面这条命令能只靠一段文本完成配对。

### 命令行

```bash
node lib/cli.js call wlan-connection.pairWithQr --json '{
  "qrText":"WIFI:T:ADB;S:studio-abc123._adb-tls-pairing._tcp;P:123456;;"
}'
```

成功返回：

```json
{
  "paired": true,
  "endpoint": { "host": "192.168.1.23", "port": 39443 },
  "serviceName": "studio-abc123._adb-tls-pairing._tcp",
  "pairingCode": "123456",
  "resolvedBy": "mdns"
}
```

`resolvedBy` 告诉你配对地址是怎么来的：

| 值 | 含义 |
|---|---|
| `mdns` | 通过 `adb mdns services` 把服务名解析成了 `host:port` |
| `qr-inline` | 二维码里直接带了 `host:port`（部分 ROM） |
| `input` | 你自己传了 `host`/`port`，跳过了发现 |

### 用图片

```bash
# 先确认本机有解码器（Windows: scoop install zbar / choco install zbar）
zbarimg --raw screenshot.png

# 再交给模块
node lib/cli.js call wlan-connection.pairWithQr --json '{"image":"screenshot.png"}'
# 或只解码不配对，先看清楚内容
node lib/cli.js call wlan-connection.decodePairingQr --json '{"image":"screenshot.png"}'
```

没有 `zbarimg` 时不会假装成功，会明确告诉你：

> 未找到二维码解码器 "zbarimg"。可安装 ZBar（Windows: scoop install zbar / choco install zbar），或改用手机把二维码扫出来后把文本传给 qrText。

我们**没有**自己实现二维码解码。二维码解码是图像算法，不可能用几十行正确实现，编一个不完整的出来只会害人。

### mDNS 查不到服务怎么办

```text
二维码里的服务 "studio-abc123…" 没有出现在 adb mdns services 的结果中。请确认手机停留在“使用二维码配对设备”界面且与电脑处于同一局域网；也可以直接传 host + port（手机“使用配对码配对设备”界面上显示的地址）。当前发现：…
```

按顺序排查：

1. 手机必须**停留在**配对码/二维码页面，离开页面服务就撤了。
2. 电脑和手机要在同一个局域网（部分路由器开了 AP 隔离，会导致 mDNS 不通）。
3. 直接传 `host` + `port` 绕过发现 —— 换成「使用配对码配对设备」页面，那里直接显示地址。

## 8. 一步到位：pairAndConnect

配对 + 连接 + 记档，一条命令解决。

```bash
# 配对码方式
node lib/cli.js call wlan-connection.pairAndConnect --json '{
  "host":"192.168.1.23",
  "port":39443,
  "code":"123456",
  "name":"小米14"
}'

# 二维码方式
node lib/cli.js call wlan-connection.pairAndConnect --json '{
  "qrText":"WIFI:T:ADB;S:studio-abc123._adb-tls-pairing._tcp;P:123456;;",
  "name":"小米14"
}'
```

参数：

| 参数 | 说明 |
|---|---|
| `host` / `port` / `code` | 配对码方式三件套，`port` 是配对端口 |
| `qr` / `qrText` / `image` | 二维码方式，与上面三件套二选一 |
| `connectPort` | 连接端口。不给的话先问 mDNS，问不到就用 5555 |
| `save` | 是否把设备写进档案，默认 `true`；传 `false` 只连不记 |
| `name` | 备注名，默认 `host:port` |

返回里有两个字段值得看：

- `connectPortResolvedBy`：`mdns` / `input` / `default`，连接端口从哪来的。
- `paired: true, connected: false`：配对成了但连不上。通常是你和手机不在一个网段，或者手机无线调试开关被关了。**配对和连接是两个结果，模块不会拿配对成功冒充连接成功。**

成功后设备档案里会同时记住两个端口：

```json
{
  "name": "小米14",
  "transport": "wifi",
  "wifi": { "host": "192.168.1.23", "port": 5555 },
  "pairingPort": 39443
}
```

下次配对授权过期时，直接拿 `pairingPort` 重配即可。

## 9. 查看 mDNS 服务

```bash
node lib/cli.js call wlan-connection.mdnsServices
```

返回会分成 `pairing` 和 `connect` 两组，正好对应前面说的两个端口：

```json
{
  "services": [
    { "name": "studio-abc123", "type": "_adb-tls-pairing._tcp", "host": "192.168.1.23", "port": 39443 },
    { "name": "adb-abc123", "type": "_adb-tls-connect._tcp", "host": "192.168.1.23", "port": 5555 }
  ],
  "pairing": [ { "name": "studio-abc123", "type": "_adb-tls-pairing._tcp", "host": "192.168.1.23", "port": 39443 } ],
  "connect": [ { "name": "adb-abc123", "type": "_adb-tls-connect._tcp", "host": "192.168.1.23", "port": 5555 } ],
  "adb": true
}
```

`pairing` 为空就说明手机没停在配对页面上。

```bash
node lib/cli.js call wlan-connection.pairingGuide
```

返回开发者选项入口、两种配对方式的逐步操作、二维码格式、三条现成的命令模板和一份排障清单。让 AI 调用这个再念给你听，比翻文档快。

## 11. 小米 HyperOS 特别说明

- 开发者选项入口：设置 → 我的设备 → 全部参数与信息 → 连点「OS 版本」7 次；再回到 设置 → 更多设置 → 开发者选项。
- 无线调试在「开发者选项 → 无线调试」，配对码和二维码两个入口都有，格式与 AOSP 一致，本模块的 `pairWithQr` 可以直接吃。
- 部分机型的二维码 `S:` 字段直接是 `host:port`，模块会自动识别并跳过 mDNS 发现。
- 如果 mDNS 一直查不到：小米的部分 ROM 对组播有限制，直接用「使用配对码配对设备」页面上的地址走 `pairWithCode` 最稳。

## 12. USB 切 TCP/IP

```bash
node lib/cli.js call wlan-connection.enableTcpip --json '{
  "serial":"R58M123456A",
  "port":5555
}'
```

然后按返回的 host:port 保存 WiFi 设备并连接：

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{"name":"测试机-WiFi","transport":"wifi","host":"192.168.1.23","port":5555}'
node lib/cli.js call wlan-connection.connect --mode wifi
```

## 13. 自动连接策略

`autoConnect` 是启动时内部调用的方法；通常不需要手工调用。推荐流程是：

1. 第一次用 `discover` 确认设备在线。
2. 用 `saveDevice` 固化设备信息。
3. 用 `setMode --mode auto --autoConnect true` 保存偏好。
4. 之后每次启动先看 `status`，再让自动连接工作。

## 14. 控制台操作

打开控制台后，进入“无线调试连接”面板：

1. 点击 Discover 刷新设备。
2. 填写 name、transport、serial 或 host、port。
3. Save Device 保存。
4. 在列表中选择设备并 Connect。
5. 通过状态卡确认 `connected`。

## 15. 常见错误

- **找不到设备**：先在终端运行 `adb devices -l`，不要先怀疑插件。
- **WiFi 连接超时**：检查 IP、端口、网络隔离、防火墙和手机无线调试开关。
- **设备 unauthorized**：解锁手机并确认授权弹窗。
- **切项目后设备还在**：这是设计行为，设备配置是全局资产；项目关联由 `project-group` 的 `deviceIds` 管理。
- **没有 ADB**：模块会启动，但连接方法会返回失败或降级；安装 Platform Tools 后重新启动 CLI。

### 配对相关

- **`Connection reset by peer` / `failed to authenticate`**：配对码或配对端口过期了。回到手机重新打开配对页面，拿新的码和端口。
- **配对成功但连不上**：用了配对端口去连接。配对端口 ≠ 连接端口，用 `pairAndConnect` 或显式传 `connectPort`。
- **mDNS 查不到 `studio-xxx`**：手机离开了配对页面，或路由器开了 AP 隔离。改用「使用配对码配对设备」页面上的 `host:port` 走 `pairWithCode`。
- **`adb 不可用（spawn adb ENOENT）`**：没装 platform-tools，或 adb 不在 PATH。装完再试，或设 `OPENGUI_PLUS_ADB` 指向 adb 绝对路径。
- **二维码解析报「不是 Android 无线调试配对二维码」**：扫错码了。确认内容以 `WIFI:T:ADB;` 开头，且来自「无线调试 → 使用二维码配对设备」而不是别的分享码。
- **配对码位数异常**：Android 配对码是 6 位数字。如果拿到的是别的长度，多半是复制时混进了别的内容。
