# 02. 模块一：无线调试连接 `wlan-connection`

## 目标

统一管理 USB、WiFi 和自动连接；保存设备配置；查询 ADB 状态；支持 Android 11+ 无线配对和 USB 切 TCP/IP。

## 1. 先发现设备

```bash
node lib/cli.js call wlan-connection.discover
```

典型返回会包含 serial、state、transport 等信息：

- `device`：已授权且在线。
- `unauthorized`：手机上没有确认 USB 调试授权。
- `offline`：设备枚举到了，但当前不可用。
- `no permissions`：电脑端 ADB 权限或驱动有问题。

Windows 常见检查：重新插拔 USB、确认手机已解锁、在手机上点击“允许 USB 调试”、执行 `adb kill-server && adb start-server`。

## 2. 保存 USB 设备

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{
  "name":"测试机-USB",
  "transport":"usb",
  "serial":"R58M123456A"
}'
```

USB 设备至少应有 `serial`。`name` 是给人看的备注名。

## 3. 保存 WiFi 设备

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{
  "name":"测试机-WiFi",
  "transport":"wifi",
  "host":"192.168.1.23",
  "port":5555
}'
```

端口默认 5555。设备和电脑必须在可互通网络中，且 Android 端已经开启无线调试或通过 USB 执行过 TCP/IP 切换。

```bash
node lib/cli.js call wlan-connection.listDevices
```

保存设备使用全局作用域，切换项目组后仍可复用。

## 4. 设置连接模式

```bash
node lib/cli.js call wlan-connection.setMode --json '{"mode":"auto","autoConnect":true}'
```

模式含义：

| 模式 | 行为 |
|---|---|
| `usb` | 优先使用 USB serial |
| `wifi` | 使用保存的 host:port |
| `auto` | 根据当前可见设备和保存配置自动选择 |

查看状态：

```bash
node lib/cli.js call wlan-connection.status
```

连接：

```bash
node lib/cli.js call wlan-connection.connect --mode auto
node lib/cli.js call wlan-connection.connect --id <deviceId>
node lib/cli.js call wlan-connection.disconnect
```

## 5. Android 11+ 配对

无线配对通常需要手机显示的配对地址、配对端口和一次性配对码：

```bash
node lib/cli.js call wlan-connection.pair --json '{
  "host":"192.168.1.23",
  "port":37123,
  "code":"123456"
}'
```

配对成功后，再用设备调试端口连接。配对端口和调试端口可能不同，不要混用。

## 6. USB 切 TCP/IP

```bash
node lib/cli.js call wlan-connection.enableTcpip --json '{
  "serial":"R58M123456A",
  "port":5555
}'
```

然后按返回的 host:port 保存 WiFi 设备并连接：

```bash
node lib/cli.js call wlan-connection.saveDevice --json '{"name":"测试机-WiFi","transport":"wifi","host":"192.168.1.23","port":5555}'
node lib/cli.js call wlan-connection.connect --mode wifi
```

## 7. 自动连接策略

`autoConnect` 是启动时内部调用的方法；通常不需要手工调用。推荐流程是：

1. 第一次用 `discover` 确认设备在线。
2. 用 `saveDevice` 固化设备信息。
3. 用 `setMode --mode auto --autoConnect true` 保存偏好。
4. 之后每次启动先看 `status`，再让自动连接工作。

## 8. 控制台操作

打开控制台后，进入“无线调试连接”面板：

1. 点击 Discover 刷新设备。
2. 填写 name、transport、serial 或 host、port。
3. Save Device 保存。
4. 在列表中选择设备并 Connect。
5. 通过状态卡确认 `connected`。

## 9. 常见错误

- **找不到设备**：先在终端运行 `adb devices -l`，不要先怀疑插件。
- **WiFi 连接超时**：检查 IP、端口、网络隔离、防火墙和手机无线调试开关。
- **设备 unauthorized**：解锁手机并确认授权弹窗。
- **切项目后设备还在**：这是设计行为，设备配置是全局资产；项目关联由 `project-group` 的 `deviceIds` 管理。
- **没有 ADB**：模块会启动，但连接方法会返回失败或降级；安装 Platform Tools 后重新启动 CLI。
