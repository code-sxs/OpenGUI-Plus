# 11. 模块十：执行可视化回放 `replay`

## 目标

记录一次任务的逐帧过程：动作、参数、是否成功、AI 决策、异常、恢复方式和可选截图；结束后导出单文件 HTML 或 JSON。

## 1. 开始录制

```bash
node lib/cli.js call replay.startRecording --json '{
  "name":"登录流程-测试机A",
  "taskLabel":"login-regression"
}'
```

记下返回的 `sessionId`。

## 2. 记录帧

```bash
node lib/cli.js call replay.markFrame --json '{
  "sessionId":"<sessionId>",
  "action":"launch com.example.app",
  "params":{"package":"com.example.app"},
  "decision":"确认当前处于桌面，先启动目标 App",
  "ok":true,
  "detail":"应用已启动",
  "captureScreenshot":true
}'
```

记录失败帧：

```bash
node lib/cli.js call replay.markFrame --json '{
  "sessionId":"<sessionId>",
  "action":"tap login",
  "params":{"x":160,"y":420},
  "ok":false,
  "anomaly":{"symptom":"按钮被弹窗遮挡","recovery":"关闭权限弹窗后重新观察"},
  "captureScreenshot":true
}'
```

`captureScreenshot` 需要 ADB；路径会写入当前数据目录的回放目录。

## 3. 结束和查看

```bash
node lib/cli.js call replay.stopRecording --sessionId <sessionId>
node lib/cli.js call replay.listReplays
node lib/cli.js call replay.getReplay --id <sessionId>
node lib/cli.js call replay.stats --id <sessionId>
```

`stopRecording` 后状态为 `ready`，会发布 `replayReady` 事件。

## 4. 事后标注

```bash
node lib/cli.js call replay.annotate --json '{
  "sessionId":"<sessionId>",
  "frameId":"<frameId>",
  "decision":"先关闭弹窗，再重新获取截图",
  "anomaly":{"symptom":"权限弹窗挡住目标按钮","recovery":"点击允许并等待页面稳定"}
}'
```

标注适合把现场结论补回历史记录，不需要重新执行任务。

## 5. 导出 HTML 和 JSON

```bash
node lib/cli.js call replay.exportReplay --json '{"id":"<sessionId>","format":"html"}'
node lib/cli.js call replay.exportReplay --json '{"id":"<sessionId>","format":"json"}'
```

HTML 是单文件，包含：

- 左侧逐帧时间线。
- 当前帧动作、状态和耗时。
- 截图、参数、AI 决策和异常恢复。
- 上一帧 / 下一帧按钮。
- 键盘左右键切换。

当前 CLI 返回 `path` 时，可直接打开该文件；若要从 HTTP 控制台访问，使用控制台提供的 `/files/` 静态路由。

## 6. 回放审计方法

按下面顺序看失败：

1. `stats` 确认失败帧和异常数量。
2. `getReplay` 看原始数据。
3. HTML 中逐帧查看截图。
4. 找第一个失败帧，不要只看最终失败。
5. 记录当时 AI 的 decision 和实际 action 是否一致。
6. 把可复用的恢复方式写入 feedback-rl。
7. 修订 demo 或 action-template。

## 7. 删除回放

```bash
node lib/cli.js call replay.removeReplay --id <sessionId>
```

这会删除会话记录和截图目录。公开分享前先确认已去除敏感截图；不要把运行目录直接提交 Git。

## 8. 与设备池组合

把 `taskId`、`deviceId`、模板版本写进 `taskLabel` 或 `detail`：

```text
batch=nightly-20260905; task=task_xxx; device=device_a; template=tpl_v2
```

这样批量失败时能根据设备和模板版本快速聚类。
