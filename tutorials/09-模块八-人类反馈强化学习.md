# 09. 模块八：人类反馈强化学习回路 `feedback-rl`

## 目标

这里的“强化学习”是工程化反馈闭环：记录人工判定、失败现象、失败步骤、解决办法和上下文；相似问题再次出现时检索经验；确认经验是否奏效。它不会自动修改模型权重，也不会在后台偷偷训练模型。

## 1. 记录一次反馈

```bash
node lib/cli.js call feedback-rl.record --json '{
  "taskLabel":"登录流程",
  "outcome":"failure",
  "symptom":"验证码区域尚未出现就点击了提交",
  "step":"tap submit",
  "resolution":"等待页面稳定并确认验证码区域存在后再提交",
  "comment":"第二次执行成功",
  "context":{"package":"com.example.app","device":"test-phone","templateId":"tpl_xxx"}
}'
```

`outcome` 一般使用 `success`、`partial`、`failure`。失败记录最好同时写 symptom、step、resolution，否则后续检索价值很低。

## 2. 查看记录和经验

```bash
node lib/cli.js call feedback-rl.listRecords
node lib/cli.js call feedback-rl.listRecords --json '{"taskLabel":"登录流程","outcome":"failure","limit":20}'
node lib/cli.js call feedback-rl.listExperiences
```

经验按命中次数排序，说明它被多少次问题检索到或复用。

## 3. 检索相关经验

```bash
node lib/cli.js call feedback-rl.queryRelevant --json '{
  "symptom":"登录提交太早，验证码还没显示",
  "limit":5
}'
```

执行模板前可以先检索，把结果作为 AI 的前置提示；执行后再把实际结果记录回去。

## 4. 标记经验是否奏效

```bash
node lib/cli.js call feedback-rl.markApplied --json '{
  "experienceId":"exp_xxx",
  "worked":true
}'
```

如果建议没有解决问题，传 `false`，并新增更准确的反馈，不要把错误经验继续标记为成功。

## 5. 查看统计

```bash
node lib/cli.js call feedback-rl.summary
node lib/cli.js call feedback-rl.successRate --taskLabel 登录流程
```

统计适合回答：某类任务是否在变稳定、失败主要集中在哪个现象、某条经验是否经常奏效。

## 6. 推荐闭环

```text
执行模板
   ↓
replay 记录动作、截图、异常
   ↓
人工查看回放并判定 success / partial / failure
   ↓
feedback-rl.record 记录原因和解决办法
   ↓
下一次执行前 queryRelevant
   ↓
markApplied 确认经验有效性
```

## 7. 经验质量规则

好的经验：

```text
现象：页面加载超过 2 秒时坐标点击落在空白处
步骤：tap login
办法：等待 1500ms，并在截图中确认登录按钮可见
上下文：App 版本、设备分辨率、模板版本
```

差的经验：

```text
“再试一次就好了”
```

反馈库是长期资产，建议保留可验证条件、动作和结果。它是跨项目知识，注意不要记录账号和敏感数据。
